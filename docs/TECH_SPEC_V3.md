## 1. כללים לכל השלבים
1. **"מרוץ נגד המחשב" לא משתנה.** כל הקוד החדש פעיל רק במצב חדר. כל הבדיקות הקיימות (כולל `test:direction`, `smoke`, `smoke:perf`) נשארות ירוקות.
2. **`src/sim` נשאר טהור** (בלי three, DOM או רשת). גם לוגיקת החדר טהורה (`src/net/room/*`), ורצה זהה בשרת, בשרת הפיתוח המקומי ובבדיקות.
3. **חוזה הכיוון לא נפגע.** הכיול קורה פעם אחת לכל כניסה לחדר. הוא נשמר בזיכרון בלבד ולא ב-storage. יש כפתור "כייל מחדש" בחדר ההמתנה, וכפתור ↔ במרוץ.
4. **גרסאות מוצמדות:** `wrangler`, `ws` (לשרת הפיתוח) ו-`@cloudflare/workers-types` אם יידרש, בגרסה מדויקת.
5. **אחרי כל שלב:** בדיקות יחידה, בנייה, בדיקת רב-משתתפים מקומית (§9), פריסה (לקוח + שרת) ודיווח בעברית עם מספר גרסה ומה לנסות.

## 2. ארכיטקטורה
```
 טלפון A ─┐                    ┌─ Durable Object "Room KRTM" ─┐
 טלפון B ─┼── WebSocket (wss) ─┤  RoomCore (טהור)               │
 טלפון C ─┘                    │  lobby · host · timer · race   │
                               │  box arbitration · scores      │
                               └────────────────────────────────┘
 GitHub Pages: המשחק (סטטי)    Cloudflare Worker: /rooms, /rooms/:code/ws
```
- **מודל הסמכות ("כל אחד אחראי על מה שלו"):**
  - כל טלפון מריץ את הסימולציה המלאה למכונית **שלו** (קלט מיידי) ומשדר את המצב שלה.
  - **המארח** מריץ גם את **הבוטים** ומשדר אותם.
  - **השרת** אחראי על: החדר, המארח, השעון, ה-seed, תחילת המרוץ, **מי לקח קופסה**, סדר הסיום והניקוד.
  - **פגיעה** נקבעת אצל **בעל המכונית הנפגעת** (מכונית אנושית: הטלפון שלה. בוט: המארח).
- **למה לא שרת שמריץ את כל הסימולציה:** עם השהיה סלולרית של 80-200 ms, היגוי בהטיה שעובר דרך השרת מרגיש "גומי". בין חברים אין צורך בהגנה מרמאות, והפתרון גם זול יותר בשרת.

## 3. קבצים
```
server/

  src/worker.js            # fetch: POST /rooms, GET /rooms/:code (exists?), GET /rooms/:code/ws (upgrade)
  src/RoomDO.js            # Durable Object: WebSocket Hibernation API, alarms, storage <-> RoomCore
src/net/
  protocol.js              # PROTOCOL_VERSION, message types, validate(msg), pack/unpack of car state
  room/RoomCore.js         # pure room state machine (no I/O): handle(msg, from, now) -> outbox; tick(now)
  room/codes.js            # room codes: 4 letters from "ABCDEFGHJKMNPQRSTUVWXYZ" (no I, L, O)
  room/scoring.js          # points 10/7/5/3/2/1, cumulative table
  nameFilter.js            # nickname cleanup + bad-word list (Hebrew + English)
  NetClient.js             # WebSocket, reconnect with backoff, clock sync, message queue
  clock.js                 # pure: server-time offset from ping samples (median)
  interp.js                # pure: snapshot buffer per remote car, interpolation / short extrapolation
src/game/
  RoomSession.js           # glue: NetClient <-> World <-> Game (one instance per room)
src/ui/
  lobby.js                 # profile (name, colour), create/join, lobby, share, scoreboard, emoji

tests/unit/room*.test.js, net*.test.js, mpSim.test.js

```
- `server/src/*` מייבא את `src/net/protocol.js`, `src/net/room/*` ו-`src/net/nameFilter.js` ישירות. wrangler מאגד אותם, כך שיש קוד אחד לחדר.

## 4. השרת (Cloudflare)
### 4.1 Worker (`worker.js`)
| בקשה | פעולה |
|---|---|
| `POST /rooms` | מגריל קוד, שואל את ה-DO `idFromName(code)` אם הוא פנוי (`/init`). אם תפוס, מגריל שוב (עד 5 ניסיונות). מחזיר `{ code }` |
| `GET /rooms/:code` | `{ exists, players, phase }`. מאפשר הודעת "חדר לא קיים" מהירה לפני חיבור |
| `GET /rooms/:code/ws` | Upgrade ל-WebSocket ומסירה ל-DO |
- **CORS ובדיקת Origin:** רק `https://galnigal-code.github.io`, `http://localhost:*` ו-`http://127.0.0.1:*`.
- **קודים לא חוקיים** (לא 4 אותיות מהאלפבית) נדחים לפני שמגיעים ל-DO.

### 4.2 Durable Object (`RoomDO.js`)
- **WebSocket Hibernation** (`ctx.acceptWebSocket`): חדר המתנה שקט לא עולה כסף. לכל socket מוצמד `serializeAttachment({ playerId })`.
- **מצב החדר** נשמר ב-`ctx.storage` בכל שינוי משמעותי (הצטרפות, יציאה, תחילה, סוף מרוץ וניקוד), כי בזמן hibernation הזיכרון נמחק. נתוני מיקום בזמן מרוץ לא נשמרים: הם רק מועברים הלאה.
- **שעונים:** `ctx.storage.setAlarm` משמש לשעון של 30 שניות, לחלון חזרה של 30 שניות אחרי ניתוק, לסיום מרוץ כפוי ולסגירת חדר ריק אחרי 10 דקות. ה-alarm קורא ל-`RoomCore.tick(now)`.
- **הגבלות:**
  - הודעה עד 1KB.
  - `state` עד 30 בשנייה לשחקן, ו-`emoji` אחת ל-3 שניות.
  - שחקן שעובר את המגבלות מנותק.
  - שחקן שביעי מקבל `error: room_full`.

### 4.3 עלות ומגבלות בתוכנית החינמית
| משאב | שימוש משוער | מגבלה חינמית |
|---|---|---|
| בקשות (20 הודעות WS נכנסות = בקשה אחת, לפי התיעוד הנוכחי) | 6 שחקנים × 15 הודעות/שנייה × 100 שנ' ≈ 9,000 הודעות ≈ 450 בקשות למרוץ | 100,000 ליום, כלומר כ-200 מרוצים מלאים ביום |
| זמן ריצה של DO | כ-2 דקות ער למרוץ | מספיק לכמה מאות מרוצים ביום |
- **שלב V3-A** יאמת את המספרים מול התיעוד העדכני ויכתוב אותם ב-STATUS. אם צריך יותר, יש תוכנית בתשלום של 5$ לחודש, אבל לא צפוי שנצטרך.

### 4.4 פריסה
- ב-`.github/workflows/deploy.yml` נוסף job בשם `deploy-server` (רץ אחרי `npm test`), עם `npx wrangler deploy` מתוך `server/`.
- **Secrets בריפו:** `CLOUDFLARE_API_TOKEN` (הרשאת "Edit Cloudflare Workers" בלבד) ו-`CLOUDFLARE_ACCOUNT_ID`.
- **כתובת השרת ללקוח:** `VITE_ROOMS_URL`, שמוגדר ב-workflow (`https://don-game-rooms.<subdomain>.workers.dev`). בלי הגדרה, הכפתורים "פתח חדר" ו"הצטרף" מוסתרים.
- **תאימות גרסאות:** הלקוח שולח `PROTOCOL_VERSION` ב-`hello`. אם יש אי-התאמה, השרת מחזיר `error: update` והלקוח מתרענן (כמו מנגנון `version.json`).

## 5. לוגיקת החדר (`RoomCore`, טהורה)
### 5.1 מצב
```js
{
  code, phase: 'lobby' | 'countdown' | 'racing' | 'results',
  hostId, raceNo, seed, goAt, lobbyTimerEnd /* null or ms */, emptySince,
  players: Map<playerId, { id, token, name, color, joinedAt, connected, lastSeen, inRace, calibrated, carId, finish: { raceTime } | null, progress }>,
  roster: [{ carId, kind: 'human' | 'bot', playerId?, name, color, slot }],   // fixed for one race
  boxes: Map<boxId, { takenUntil /* race time */ }>,
  scores: Map<token, { name, color, points, wins, races }>,
}
```
- **`playerId`** הוא מספר רץ בחדר. **`token`** הוא UUID שהלקוח שומר ב-`sessionStorage` לכל חדר, והוא מאפשר חזרה אחרי ניתוק. **הניקוד נשמר לפי `token`**.

### 5.2 מעברים
| אירוע | תוצאה |
|---|---|
| `hello` (שחקן חדש, lobby) | נכנס. צבע תפוס מוחלף בפנוי הראשון מ-`PLAYER_COLORS` (8 צבעים). שם עובר `nameFilter`. אם אין מארח, הוא המארח |
| `hello` בזמן `racing` | נכנס כצופה (`inRace: false`), מקבל `race_start` כדי לראות את המרוץ |
| `hello` עם `token` קיים (חזרה) | מתחבר לאותו שחקן, כולל `inRace` והמכונית שלו |
| מספר בני האדם המחוברים ב-lobby ≥ 4 | `lobbyTimerEnd = now + 30 s` (אם לא רץ כבר) |
| מספר יורד מתחת ל-4 | השעון נעצר (`lobbyTimerEnd = null`) |
| `start_now` מהמארח, או השעון נגמר | `startRace()` (ראה 5.3) |
| ניתוק | `connected = false`. אחרי 30 שניות בלי חזרה, השחקן יוצא מהחדר. במרוץ המכונית שלו נעצרת וממשיכה בשקיפות ואז נעלמת, והוא לא מקבל ניקוד |
| המארח יצא (או לא חזר תוך 5 שניות במרוץ) | המארח החדש הוא בן האדם המחובר הוותיק ביותר. נשלח `host` לכולם. המארח החדש מאמץ את הבוטים (§6.6) |
| כל בני האדם שבמרוץ סיימו, או 25 שנ' אחרי הסיום הראשון, או 150 שנ' מ-GO | `endRace()`: סדר לפי `finish.raceTime`, ואחריו מי שלא סיים לפי `progress` (s). ניקוד, `phase = 'results'`, ואחרי 8 שניות `phase = 'lobby'` |
| אין אף מחובר | אחרי 10 דקות החדר נמחק (`storage.deleteAll`) |

### 5.3 `startRace()`
- **`seed`** אקראי. **`raceNo++`**.
- **`roster`:** בני האדם המחוברים שעשו כיול, בסדר הצטרפות, ובוטים משלימים עד 4 (`max(0, 4 - humans)`). שמות הבוטים והצבעים מוגרלים מה-seed.
- **מקומות בגריד:** מוגרלים מה-seed (6 מקומות, §6.1).
- **`goAt = now + 4000`**: 0.5 שנייה להורדת המסלול לטלפון ו-3.5 שניות ספירה.
- נשלח `race_start { raceNo, seed, roster, goAt, hostId }`.
- **שחקן שלא סיים כיול** נשאר צופה במרוץ הזה (בפועל זה נדיר, כי הכיול קורה מיד עם הכניסה לחדר).

### 5.4 קופסאות (שיפוט)
1. הלקוח שמכונית שלו (או בוט, אצל המארח) עוברת בקופסה מתחיל רולטה **מיד**, באופן אופטימי, ושולח `box_take { boxId, carId, raceTime }`.
2. השרת מאשר אם `raceTime >= takenUntil`, ואז קובע `takenUntil = raceTime + BOX_RESPAWN`. אחרת הוא דוחה.
3. השרת משדר `box { boxId, carId, ok }`.
4. **אם נדחה** (מישהו אחר היה ראשון), הלקוח מבטל את הרולטה. זה קורה כמעט רק כשתי מכוניות נוגעות בקופסה באותו רגע.
5. **מי שלוקח מגריל את הפריט** בעצמו לפי המקום שלו, עם ה-rng המקומי. הבחירה לא צריכה להיות זהה אצל כולם, ורק השימוש בפריט משודר.

### 5.5 ניקוד (`scoring.js`)
- **נקודות:** 10, 7, 5, 3, 2, 1 לפי המקום **בין בני האדם** (בוטים מדולגים). מי שהתנתק ולא חזר מקבל 0.
- **הטבלה** ממוינת לפי נקודות, אחר כך מספר ניצחונות, אחר כך מספר מרוצים.

## 6. שינויים בסימולציה (`src/sim`)
### 6.1 עולם מרובה משתתפים
- **`createWorld({ track, seed, roster, localCarIds })`:**
  - `roster` כמו ב-5.3. `localCarIds` הם המכוניות שהטלפון הזה מריץ: המכונית שלו, ועוד הבוטים אם הוא המארח.
  - בלי `roster` ההתנהגות זהה להיום (מרוץ נגד המחשב, בדיקות קיימות).
- **`GRID`** מורחב ל-6 מקומות: `[-6,±3], [-12,±3], [-18,±3]`.
- **`car.owner`:** `'local'` או `'remote'`.
  - `world.step` מריץ `stepCar`, פריטים ובוטים **רק** למכוניות מקומיות.
  - מכוניות מרוחקות מקבלות את השדות שלהן מ-`interp.js` לפני כל צעד: `s, d, h, vy, yaw, speed, steer, state, turboT, shieldT, hit.kind/t, gunSlow`.
- **`world.player`** הוא המכונית המקומית האנושית. HUD, מצלמה וסאונד ממשיכים לעבוד בלי שינוי.

### 6.2 התנגשויות (`collisions.js`)
- זוג שבו **שתי המכוניות מרוחקות** לא מחושב בכלל. בעליהן מחשבים אותו.
- בזוג שבו מכונית אחת מקומית, **ההפרדה והדחף מוחלים רק על המקומית**. החצי השני מחושב באותו אופן אצל הבעלים של המכונית השנייה.
- בגלל הסימטריה של הנוסחה, התוצאה הכוללת קרובה למה שקורה היום. ההבדל הוא רק השהיה של כ-100 ms בתגובה של הצד השני.
- **אירוע `bump`** (ניצוצות, רעידה, צליל) מוצג אצל כל אחד לפי מה שהוא רואה.

### 6.3 פריטים וישויות
- **מזהה ישות** הופך למחרוזת `"<carId>-<n>"`, כדי שיהיה ייחודי בין טלפונים. מכשולים קבועים נשארים עם מספרים.
- **`useItem`** במכונית מקומית יוצר את הישות מקומית ושולח `item { id, type, s, d, targetId, raceTime }` (מוקש/שמן/חבית/טיל), או `gun { carId, raceTime }`, או `shield`.
- **אצל המקבל:** הישות נוצרת עם `age = now - raceTime`. טיל וקליעים "מורצים קדימה" לפי ה-age, כך שהם נמצאים באותו מקום בערך כמו אצל השולח.
- **`stepEntities`** בודק פגיעה רק מול **מכוניות מקומיות**. כשיש פגיעה, נשלח `hit { entityId, carId, kind }`.
  - כולם מסירים את הישות. השמן נשאר, כמו היום.
  - האפקט על המכונית הנפגעת מגיע ממילא בזרם המצב שלה (`hit.kind`).
- **תנועת טיל:** הטיל עוקב אחרי `target.d` לפי מה שכל טלפון רואה. אם יש סטייה קטנה, הנפגע הוא שקובע.

### 6.4 בוטים ו"גומי"
- **בוטים רצים רק אצל המארח.**
- **בחדר, הגומי משווה כל בוט לבן האדם הקרוב אליו** ולא ל-`world.player`. כך הבוטים נשארים בתוך החבורה.
- **בני אדם לא מקבלים שום תיקון מהירות.** מרוץ בין חברים הוגן.

### 6.5 סיום וזמן
- **זמן מרוץ:** `raceTime = serverNow() - goAt` (שניות). כל הטלפונים מסונכרנים לשעון השרת (§7.2).
- **סיום:** מכונית מקומית שעוברת את `finishS` שולחת `finish { carId, raceTime }`. התוצאות הרשמיות מגיעות מהשרת ב-`results`.
- **ה-safety net הקיים** (`FORCE_FINISH_AFTER`) כבוי בחדר. השרת אחראי לסיום כפוי.

### 6.6 החלפת מארח באמצע מרוץ
- המארח החדש יוצר מוח בוט (`createBrain`) לכל בוט, מהמצב האחרון שהתקבל (interp).
- הבוטים הופכים ל-`local` אצלו, והוא ממשיך לשדר אותם. ייתכן "קפיצה" קטנה, וזה מקובל.

## 7. רשת בצד הלקוח
### 7.1 הודעות (`protocol.js`, JSON)
| כיוון | סוג | תוכן |
|---|---|---|
| ← | `hello` | `{ v, token, name, color }` |
| → | `welcome` | `{ you: playerId, room, serverNow }` |
| → | `room` | lobby: שחקנים, מארח, phase, `lobbyTimerEnd`, ניקוד |
| ← | `calibrated`, `start_now`, `leave`, `emoji {e}` | |
| ← | `ping {c}` / → `pong {c, s}` | סנכרון שעון |
| → | `race_start` | §5.3 |
| ← → | `st` | מצב מכונית, 15 בשנייה: `[carId, raceTimeMs, s*100, d*100, h*100, yaw*1000, speed*10, steer*100, stateCode, fxBits, hitCode, hitT*100]` (מערך מספרים שלמים, כ-60 בתים) |
| ← → | `bots` | מהמארח: מערך של `st` לכל הבוטים, בהודעה אחת |
| ← → | `item`, `gun`, `shield`, `hit` | §6.3 |
| ← / → | `box_take` / `box` | §5.4 |
| ← | `finish` | §6.5 |
| → | `results` | `{ order: [{carId, raceTime|null}], scores }` |
| → | `host`, `player_left`, `error {code}` | `code`: `room_full`, `no_room`, `update`, `rate` |
- **הודעות `st`, `bots`, `item`, `hit` ו-`emoji`** מועברות על ידי השרת לכל שאר המשתתפים כמו שהן, בתוספת `from`.

### 7.2 סנכרון שעון (`clock.js`)
- נשלחים 5 פינגים בכניסה, ועוד אחד כל 5 שניות.
- `offset = serverTime - (sent + rtt/2)`. בוחרים את החציון מהדגימות עם ה-RTT הנמוך ביותר.
- **בדיקת יחידה:** עם השהיה אקראית לא סימטרית, השגיאה קטנה מ-30 ms.

### 7.3 אינטרפולציה (`interp.js`)
- לכל מכונית מרוחקת יש חוצץ של 12 דגימות. היא מוצגת ב-`raceTime - 0.12 s` באינטרפולציה לינארית. `yaw` עובר נרמול זוויות.
- **אם אין דגימה חדשה,** המכונית ממשיכה בתחזית עד 0.25 שנייה, ואז קופאת ומקבלת שקיפות 50% עם סימן 📶.
- **בדיקות יחידה:** תנועה חלקה עם ריצוד של ±50 ms, דגימות שהגיעו בסדר שגוי, ותחזית שלא חורגת מהכביש (חיתוך ל-`halfWidth`).

### 7.4 `NetClient`
- **חיבור מחדש אוטומטי:** 0.5, 1, 2 ו-4 שניות, עם אותו `token`.
- **`visibilitychange`:** כשהמסך חוזר, אם ה-socket נסגר, מתחבר מחדש מיד.
- **Wake Lock** פעיל בחדר ההמתנה ובמרוץ (כבר קיים במרוץ).

## 8. ממשק (`lobby.js`, `screens.js`, `ui.css`)
- **תפריט:** "מרוץ נגד המחשב", "פתח חדר", "הצטרף לחדר". שני האחרונים מוצגים רק אם `VITE_ROOMS_URL` מוגדר.
- **פרופיל** (פעם ראשונה, ניתן לשינוי מהתפריט): כינוי עד 12 תווים, ו-8 עיגולי צבע. נשמר ב-`localStorage` (`dongame.profile`).
- **הצטרף:** 4 תיבות אותיות שמדלגות אוטומטית, באותיות גדולות ובכתיבה LTR. `?room=KRTM` בכתובת מדלג ישר לחיבור.
- **חדר ההמתנה:**
  - הקוד מוצג בגדול (LTR).
  - **"שתף בוואטסאפ":** `navigator.share` אם קיים. אחרת `https://wa.me/?text=` עם "בוא למרוץ! קוד KRTM" וקישור.
  - **"העתק קישור".**
  - רשימת שחקנים עם עיגול צבע, 👑 למארח, ✓ למי שכויל ו-📶 למי שמנותק.
  - שעון 30 שניות בגדול, ו"התחל עכשיו" (למארח בלבד).
  - טבלת ניקוד, "כייל מחדש" ו"צא מהחדר".
- **כיול:** אותו מסך קיים, שמופעל אוטומטית בכניסה לחדר. בסופו נשלח `calibrated`.
- **במרוץ:** אותו HUD, ו-6 שחקנים בפס ההתקדמות.
  - **כפתור 😀** קטן למעלה, ליד ↔, פותח 4 אימוג'ים. הבועה מופיעה 2 שניות מעל המכונית (sprite) אצל כולם, ומעל המכונית שלך אצלך.
  - **שם החבר** מעל כל מכונית מרוחקת, כמו בבוטים היום.
- **תוצאות:** טבלת המרוץ עם הנקודות שנוספו, והטבלה המצטברת. אחרי 8 שניות חזרה אוטומטית לחדר.
- **צופה (מצטרף באמצע):** מצלמת הצפייה הקיימת על המוביל, עם הכיתוב "צופה, תיכנס למרוץ הבא".
- **שגיאות בעברית:** "החדר לא קיים", "החדר מלא (6)", "אין חיבור, מנסה שוב…", "יש גרסה חדשה, מרענן…".
